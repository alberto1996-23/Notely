# Notely

A local Markdown notes app built with Next.js App Router, TypeScript, and Server Actions. Create, read, edit, delete, search, and organize notes with tags.

## Architecture

A note is `{ id, title, body, tags, createdAt, updatedAt }`. Its stable slug identifies `notes/<slug>.md`; changing the title does not break links. Each file contains a small, explicitly supported YAML frontmatter subset and the Markdown body. Server Components read files and render lists, tags, and note pages. Client Components own only interactive editor, delete, and search controls. Server Actions validate writes, detect stale revisions, atomically replace files, invalidate cached pages, and redirect after success. The only runtime libraries beyond Next.js/React are `marked` and `sanitize-html`.

## Setup

Use Node.js **22.18+** (Node 24 LTS also works). The Node version requirement enables the built-in TypeScript test runner without another test dependency.

```sh
npm ci
npm run dev
```

Open <http://127.0.0.1:3000>. No `.env`, database, or authentication service is needed to run the app. Existing `GH_APP_ID` and `GH_APP_SECRET` values are repository automation credentials and are never read by application code or exposed to the browser. Do not prefix them with `NEXT_PUBLIC_`.

To validate and run the production build:

```sh
npm test
npm run build
npm run typecheck
npm start
```

Run only one app process against a given notes directory. The app binds to loopback by default because it deliberately has no authentication. It requires a writable local disk and the Node.js runtime; ephemeral serverless filesystems, Edge runtime, and static exports are not suitable for persistence. Back up `notes/` yourself. New personal notes are ignored by Git; the welcome example is tracked.

## File format

```markdown
---
id: "example"
title: "A title with a colon: and quotes"
tags: ["learning", "markdown"]
createdAt: "2026-09-09T12:00:00.000Z"
updatedAt: "2026-09-09T12:00:00.000Z"
---
# My note

The body starts immediately after the closing delimiter.
```

The five metadata keys are required, unique, and the only supported keys. String values must use JSON double-quoted syntax and tags must be a JSON array of strings. This is valid YAML, but **not a general YAML parser**: unquoted values, comments, block scalars, and block lists are deliberately unsupported. Use the editor or follow the example when editing files manually. Keep the filename and `id` identical and advance `updatedAt` after an external edit. Invalid files surface an error instead of being silently discarded.

Slugs contain lowercase ASCII letters, numbers, and hyphens; `new` is reserved for the create route. Generated slugs append a UUID to a readable title prefix, including for duplicate titles. Tags are normalized to lowercase, deduplicated, and limited to 20 tags of up to 40 letters/numbers/hyphens/underscores each. Titles are required (up to 200 characters); bodies allow 100,000 characters. Slugs are validated before constructing paths and symlinks are refused on reads.

## Manual verification checklist

- [ ] Open `/`; the welcome note appears. Open it and verify headings, lists, links, and code formatting.
- [ ] Open `/notes/new`. Enter a title, body, and comma-separated tags. Verify preview updates alongside the textarea (below it on narrow screens).
- [ ] Save. Verify the read route and the complete `notes/<slug>.md` file. Refresh and restart the app; the note persists.
- [ ] Create another note with the same title; verify both have different URLs. Try a title consisting only of non-Latin characters; creation still works.
- [ ] Edit a note, rename it, change its body, and remove/add tags. Save; the URL and creation time stay stable while the update time advances.
- [ ] Open the same note in two edit tabs. Save one, then save the older draft. The second save shows a conflict and retains the draft.
- [ ] Enter text found only in a body into search. Results update after 300 ms and `?q=...` appears. Refresh or paste that URL into another tab on the same app; the input and results agree.
- [ ] Clear search; all notes return. Search uses case-insensitive AND matching of whitespace-separated terms across title and body.
- [ ] Select multiple tags; only notes containing **all** selected tags appear. Combine with text search. Navigate away and use Back; input, checkboxes, and results reflect the restored URL.
- [ ] Visit `/tags`; verify counts, open a tag, and combine the fixed tag with search and another tag.
- [ ] Enter `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>`, and `[bad](javascript:alert(1))` in a note. Both preview and saved read view must remain safe; scripts, images, and unsafe URLs are stripped.
- [ ] Cancel a delete confirmation; the note remains. Confirm deletion; the file disappears and all notes/tag counts update.
- [ ] Visit a missing note, its edit route, and a missing tag; the not-found UI appears.
- [ ] Tab through navigation, search, editor, and save controls. Check a narrow viewport; the editor stacks and wide code blocks/tables scroll within their containers.

See [the teaching notes](docs/teaching-notes.md) for the routing, editing, and search tradeoffs.
